# ClubShell — IPC Protocol (Shell ⇄ Agent)

Status: normative. Protocol version `v = 1`.

Implementations: `src/ClubShell.Agent/Ipc/*` (server: `PipeServer`, `MessageDispatcher`, `Handlers/*`),
`crates/winutil/src/pipe.rs` (`PipeClient`: framing, heartbeat, pending requests) + `apps/shell/src-tauri/src/agent/*`
(transport, reconnect supervisor, event forwarder), `crates/protocol/src/ipc.rs` (Rust types),
`src/ClubShell.Contracts/Ipc/*` (C# types), `packages/contracts-ts/src/commands.ts` (`IpcEnvelope`, `IpcError`,
`ErrorCode`, `AgentEventMap`).

Section 6 of this document is the canonical catalogue of domain DTOs; `SERVER_API.md` and
`TAURI_COMMANDS.md` reference it and never redefine a type.

---

## 1. Transport

| Property | Value |
|----------|-------|
| Pipe name | `\\.\pipe\clubshell-agent` (configurable `agent.json → ipc.pipeName`) |
| Mode | Byte stream (`PipeTransmissionMode.Byte`), duplex, overlapped (`PipeOptions.Asynchronous`); message boundaries come only from the length prefix. |
| Instances | `ipc.maxConnections` (default 4). One is the Shell; the others are for diagnostics clients running as SYSTEM or a member of `Administrators`. |
| DACL | `SYSTEM` and `BUILTIN\Administrators` full control; kiosk user SID `ReadWrite \| Synchronize` allow + `CreateNewInstance` deny; no other ACE (`PipeSecurityFactory.Create`). Every accepted connection is additionally validated by client process (`GetNamedPipeClientProcessId` → token SID, session, image path; `SECURITY.md` §3.2), so a remote (SMB) client cannot pass. |
| Framing | `[u32 length LE][UTF-8 JSON bytes]`. `length` = byte count of the JSON, **excluding** the 4-byte prefix. |
| Max frame | 4 MiB = 4 194 304 bytes of JSON. A larger `length` → receiver closes the connection with `protocolError`. |
| Encoding | UTF-8 without BOM, no trailing newline. |
| Ordering | Frames are processed in the order received per connection; responses may be returned out of order (correlate by `id`). |
| Rate limit | `ipc.requestsPerSecond` token bucket per connection (default 50/s sustained, burst = twice that). Excess → `rateLimited{retryAfterSec: 1}` response, connection kept. |
| Idle | Connection without `auth.hello` within 5 s → closed. |

The pipe is a byte stream: readers accumulate until `length` bytes follow the prefix, so the protocol also
works over other byte-stream transports (`tokio::io::duplex` in the Rust tests, TCP/Unix sockets in dev).

## 2. Envelope

Every frame is exactly one `IpcEnvelope`:

```json
{
  "v": 1,
  "id": "6f1d2c4e-1b3a-4a7c-9f7d-0e6f2b5a9c11",
  "kind": "request",
  "name": "session.start",
  "ts": "2026-09-21T10:15:30.123Z",
  "payload": { "tariffId": "b1a5b6b4-3f6e-4b7f-8c26-1d0e2e5c9a10", "minutes": 60, "prepaid": true },
  "error": null
}
```

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `v` | int | yes | Protocol major. Receiver rejects `v` outside its supported set with `versionMismatch`. |
| `id` | string (uuid v4) | yes | Request id generated by sender. Response copies it. Events use a fresh id. |
| `kind` | `"request"` \| `"response"` \| `"event"` | yes | |
| `name` | string `<domain>.<action>` | yes | For a response equals the request name (exception: `sys.ping` → `sys.pong`). |
| `ts` | string ISO-8601 UTC ms | yes | Sender wall clock. Informational only, never used for ordering. |
| `payload` | object \| null | yes (key present) | Request/response body or event data. `null` when the message has no data. Never an array or scalar at top level. |
| `error` | `IpcError` \| null | yes (key present) | Non-null only on `kind = "response"`. When non-null, `payload` MUST be `null`. |

`IpcError`:

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `code` | `ErrorCode` | yes | Section 5. |
| `message` | string | yes | Human-readable, English, safe to display in dev; UI shows localized text keyed by `code`. |
| `details` | object \| null | yes | Structured extra (e.g. `{ "field": "minutes", "min": 15 }`, `{ "retryAfterSec": 3 }`). |

Rules:

1. A `request` MUST receive exactly one `response` with the same `id`, within `shell.ipc.requestTimeoutMs`
   (client-side timeout → synthetic `timeout` error). Long operations (`games.launch`) MUST still respond
   within the timeout; progress goes through events.
2. An `event` never gets a response.
3. Unknown `name` on a request → response `notFound` with `details: { "name": "<name>" }`.
4. Malformed JSON or envelope → response `protocolError` if `id` could be parsed, otherwise the connection
   is closed.
5. Before `auth.hello` succeeds, every request other than `auth.hello` → `unauthorized`.
6. Request payload validation failure → `validation` with `details: { "field": "<jsonPath>", "reason": "<code>" }`.

## 3. Handshake

```
Shell ──▶ Agent  request  auth.hello  { shellToken, shellVersion, pid, wtsSessionId, locale, capabilities }
Agent ──▶ Shell  response auth.hello  { agentVersion, protocol, pcId, pcName, zone, serverOnline, policyVersion, serverTime, capabilities, kioskUser }
```

- `shellToken` = contents of `C:\ProgramData\ClubShell\secure\shell.token` (64 hex chars). Agent compares
  in constant time; mismatch → `unauthorized` and connection closed after the response is flushed.
- Agent also verifies the client process before any frame is read: `GetNamedPipeClientProcessId` → token SID
  must be the kiosk user (running from `shell.exePath`) or SYSTEM / a member of Administrators (diagnostics).
  Mismatch → the connection is closed without a response (`SECURITY.md` §3.2).
- `capabilities` advertised by the Agent (string[]): `accountPool`, `cloudSave`, `remoteControl`,
  `screenCapture`, `virtualKeyboard`, `wol`, `offline`, `shop`, `chat`, `booking`, `tournaments`. The
  Shell hides features whose capability is absent.

Repeat `auth.hello` on an authenticated connection is allowed (idempotent; refreshes `shellVersion`).

## 4. Heartbeat

Shell sends `sys.ping` every 5 s (`ipc.heartbeatIntervalSec`). Agent responds `sys.pong`.

| Side | Missed | Action |
|------|--------|--------|
| Shell | 3 consecutive pongs not received within 5 s each | Close pipe, reconnect with backoff `shell.ipc.reconnectMinMs..reconnectMaxMs`, re-hello, emit `kiosk://connectivity {agent:"disconnected"}` |
| Agent | no `sys.ping` for 3 × 5 s on the Shell connection | Terminate Shell process, watchdog restarts it |

Ping/pong are exempt from rate limiting and are not logged above Verbose.

## 5. Error codes

`ErrorCode` (shared verbatim with `SERVER_API.md` and Tauri `ShellError`). Wire literal = camelCase.

| Wire value | Member | HTTP equiv | Meaning |
|------------|--------|-----------|---------|
| `unauthorized` | Unauthorized | 401 | Not authenticated / bad token / bad credentials |
| `forbidden` | Forbidden | 403 | Authenticated but not allowed (role, SID, capability) |
| `notFound` | NotFound | 404 | Entity or message name unknown |
| `validation` | Validation | 400 | Payload invalid; `details.field` |
| `conflict` | Conflict | 409 | State conflict (duplicate, out of stock, already joined) |
| `insufficientFunds` | InsufficientFunds | 402 | Balance too low; `details: {required: Money, available: Money}` |
| `sessionNotActive` | SessionNotActive | 409 | Operation needs an Active/Paused session |
| `sessionAlreadyActive` | SessionAlreadyActive | 409 | `session.start` while a session exists |
| `gameNotInstalled` | GameNotInstalled | 409 | `installed = false` or install path missing |
| `gameLaunchFailed` | GameLaunchFailed | 500 | Launcher error; `details: {stage, exitCode?, stderr?}` |
| `accountPoolExhausted` | AccountPoolExhausted | 409 | No free pooled account |
| `antiCheatBlocked` | AntiCheatBlocked | 403 | Anti-cheat prerequisite failed; `details: {kind, reason}` |
| `policyDenied` | PolicyDenied | 403 | Blocked by Policy; `details: {rule}` |
| `agentOffline` | AgentOffline | 503 | Agent has no server connection and operation cannot be served from cache |
| `serverUnavailable` | ServerUnavailable | 503 | Server returned 5xx / circuit open |
| `timeout` | Timeout | 504 | Upstream or launch timeout |
| `rateLimited` | RateLimited | 429 | `details.retryAfterSec` |
| `internal` | Internal | 500 | Unexpected exception; `details.traceId` |
| `protocolError` | ProtocolError | 400 | Envelope/framing violation |
| `versionMismatch` | VersionMismatch | 426 | Protocol/app version unsupported; `details: {supported: [..], got}` |

Any request may additionally return `internal`, `protocolError`, `rateLimited`, `timeout`, `unauthorized`
(before hello) — these are not repeated in the per-message tables.

`date` = `YYYY-MM-DD`; `time` = `HH:mm` (24 h, local club time). Enum wire values are camelCase strings;
member names (C#/Rust/TS) are PascalCase.

## 9. Sequences

### 9.1 Reconnect

```
Shell: pipe error → clear pending (reject with timeout) → emit kiosk://connectivity{agent:"disconnected"}
       → backoff → CreateFile → auth.hello → auth.status/session.get → emit kiosk://connectivity{agent:"connected"}
Agent: connection dropped → nothing (all state is agent-side)
```

### 9.2 Session timeout

```
t = endsAt − 10m : event session.warning{10}   (warningsSent += 10)
t = endsAt − 5m  : event session.warning{5}
t = endsAt − 1m  : event session.warning{1}
t = endsAt       : event session.warning{0}; state → ending; Shell shows "extend?" for graceSec
t = endsAt+grace : POST /sessions/{id}/end (or outbox) → state ended → event session.ended{timeUp}
                   → kill job object (games) → release leases → event shell.command{lock}
```

### 9.3 Message size / batching

No batching. One request per frame. Lists are paginated to keep frames far below 4 MiB (Game catalogue
of 500 items ≈ 400 KiB).
